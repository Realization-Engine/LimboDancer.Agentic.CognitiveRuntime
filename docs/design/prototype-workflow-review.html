UX REVIEW / 6 OCTOBER 2026 / PROPOSAL ONLY

Make the next command clear.

Campaign Atlas has a coherent command model. Its interface should show where the user is, what is ready, and what happens next, while protecting work between headquarters.

Reviewed scope: prototypes/europe-hex-map

Reviewed commit: 84242283f24ab82ced4658e57ae0640421a3678a

Organize around the user's task.

Offer two starting points: Explore the atlas and Run a command exercise. Within an exercise, keep the active headquarters, mission, save state, and next action visible together.

The interface puts campaign management, theater navigation, command planning, map controls, and research into one scrolling sidebar. It is 280 px wide at overview scale and expands to 350 px inside a theater. Disclosures reduce initial clutter, but obscure the sequence of work.

Keep: the map as the primary spatial surface, the field-manual palette, explicit source dates, stable unit identities, authority constraints, and distinctions between historical reference and authored exercise content. Existing next-step text and contextual action filtering are useful foundations.

Method: source-based expert review, not a usability study. The worktree prototype tree matches the GitHub main tree retrieved for this review: fb5b6079f778d71b4a2dc425eaa8311c1267e187. Browser security blocked local-file navigation. No rendered screenshot, interactive walkthrough, or measured usability result is claimed. Layout and comprehension effects below are hypotheses; code behavior is identified explicitly.

Make the journey visible.

Current entry: choose Western Europe, enter the automatically opened Theater workspace, expand Dated campaigns, and select Normandy. Other theaters offer geography browsing but no dated campaign package. The initial campaign controls are disabled, including an empty saved-Situation selector, while Clear campaign data appears first.

The command loop repeats down First Army → V Corps → Division → Regiment → Battalion, and reports return upward. Use a branching command tree with local mission stages, rather than a global percentage-complete bar.

Suggested stages: Draft → Order queued → Received → Plan saved → Executing → Report queued → Reviewed. Show only information known to the current headquarters. Preserve delivery receipts and assessment delays.

Prioritized findings

P1 / LOST WORK

Preserve drafts when navigating.

Confirmed: selecting a headquarters or mission clears the regional text field. Advancing communications also clears it, although that operation does not save the text as a plan. Loading another theater package clears an unsaved sector note.

Change: retain drafts by campaign, headquarters, mission, and action. Distinguish Draft saved from Plan saved or Report sent. On storage failure, retain the text and offer Copy draft.

Accept when: a typed plan survives navigation, communication delivery, and reload without being issued accidentally.

regional-view.js: changeRegional, navigate, mission onclick. theater-view.js: loadWorkspace.

P1 / RESET AND RECOVERY

Move reset out of the primary path.

Confirmed: Clear campaign data immediately removes exercise saves for the active seed, including earlier reference-package versions, with no confirmation or undo. New campaign changes the seed; old keyed records remain, but there is no visible campaign library.

Change: put Restart exercise in a campaign menu, state its deletion scope, and offer a recoverable archive. Separate New exercise from Advanced: map seed. Add a named exercise library and a validated restore path before calling JSON exports backups.

Accept when: users can cancel a reset and restore a prior exercise through the interface.

regional-view.js: clearRegionalExercise. app.template.js: newCampaign.

P1 / SETUP TRAP

Resolve setup before opening a Situation.

Confirmed: Open Situation appears before engagement preparation. Opening creates and saves formation state. Catalog-backed tactical-test preparation is then disabled and the model rejects it. Returning to the card does not remove the restriction.

Change: make the first action Prepare Situation. Offer Maneuver only or Tactical test setup, describe the authored opponent, and explain prerequisites. Later openings become Resume Situation. Any rebuild must preserve a snapshot and explain the progress it resets.

Accept when: ordinary navigation never silently commits a setup choice.

situation-view.js: renderSituation. formation-view.js: openFormation. tactical-handoff.js: prepare.

P1 / KEYBOARD BLOCKER

Provide keyboard sector selection.

Confirmed: overview and theater/regional hexes have click handlers without keyboard semantics. Creating a Situation requires selecting a regional sector. Formation hexes support keyboard activation, but each is a separate tab stop.

Change: provide a searchable sector list synchronized with the map. Use one map tab stop with arrow navigation and Enter to select. Announce selections, show focus, and move focus to the new workspace heading on navigation.

Accept when: Situation creation works entirely by keyboard without tabbing through every cell.

app.template.js: DATA.cells loop. theater-view.js: loadWorkspace. formation-view.js: renderFormation.

P2 / DISCOVERABILITY

Give exercises a direct entrance.

Confirmed: the dated exercise is inside a nested disclosure. Saved Situations become available only after opening the regional campaign. Five theaters lack dated packages.

Change: provide Start Normandy exercise and Resume exercise alongside Explore atlas. Label unsupported theaters Geography only before selection. An exercise selection should open its theater and dated package automatically.

Accept when: users can reach the briefing directly from the landing state without discovering a nested selector.

viewer.html: campaignActions, regionalEntry. regional-view.js: renderRegional, renderCampaignActions.

P2 / COMMAND COMPREHENSION

Connect each action to its effect.

Confirmed: next-step text exists, but the communication action is farther down the panel. One field serves plans, reports, and assessments. Advancing communications delivers due messages globally without advancing campaign time.

Change: place the current action next to mission status: Issue order, Save plan, Send report, Review report, or Advance communications. Preview deliveries, label the writing field for its purpose, and list prerequisites for unavailable steps.

Accept when: users understand their authority and whether an action changes time. Previews must not reveal undelivered reports to recipients.

regional-view.js: regionalNext, regionalAdvance. regional-state.js: advance, status, messages.

P2 / MAP FEEDBACK

Show legal moves before failed clicks.

Confirmed: every formation cell invokes movement; invalid phase, side, adjacency, occupancy, or budget is rejected afterward. Complete phase uses the same label across all phases. Six phases record passes without their named effects. Contact stops progress pending an unavailable integration.

Change: highlight legal destinations and costs; group side, posture, and movement allowance. Label unsupported phases Pass phase: effects unavailable. At contact, offer Return to Situation and relevant exports, with an explicit explanation that campaign continuation from tactical results is unavailable.

Accept when: users identify a legal move and understand the contact stop without triggering an error first.

formation-view.js: renderFormation. formation-state.js: move, next.

P2 / INFORMATION HIERARCHY

Separate decisions from evidence.

Confirmed: scope notes, source links, internal IDs, commands, and several export types share the sidebar. Below 750 px, CSS places the map above controls. The effect on scanning and touch use needs visual validation.

Change: keep concise capability labels visible and move detailed evidence to an inspector. Default to formation names. Group exports by purpose: map image, exercise record, Situation record, ASL draft, or standalone ASL test card. Explain format, exclusions, destination, and restore support.

Accept when: users distinguish a standalone test card from a blocked campaign handoff and inspect evidence without losing their mission.

viewer.html, site.css, situation-view.js.

Smaller widths: collapse the command tree into a drawer and switch between Map and Mission while retaining selection, scroll position, and drafts. Keep headquarters context and the primary action visible. Set breakpoints from usable panel width.

Disclosure: keep labels such as Modern reference, Authored exercise, and Combat unavailable beside the decision they affect. Detailed evidence remains one action away. Do not hide a limitation that changes the user's choice.

Validate through tasks.

Run a formative study with five participants spanning new and experienced users. These are proposed targets, not measured results.

  1. Start: open Normandy from a fresh session. Target: four of five without help within 60 seconds.
  2. Delegate: issue, deliver, and plan an order. Target: four of five explain their current headquarters and why the next branch unlocks.
  3. Interrupt: leave a half-written plan, advance communications, return, and reload. Target: zero draft loss.
  4. Prepare: at a battalion, select a sector and set up the opponent before opening the map. Target: four of five without restarting.
  5. Maneuver: identify a legal move and explain the contact stop, including unavailable combat reconciliation.
  6. Export: choose the ASL Studio test card and explain why its result cannot update the campaign.
  7. Access: create a Situation with keyboard only. Check focus and screen-reader announcements. Test at 200% zoom and roughly 390, 768, and 1440 px widths.

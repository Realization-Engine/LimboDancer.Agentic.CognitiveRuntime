## Build (rulings R71.9, R71.10)
1. **The SAN (R71.9).** A new event `san-reduced` (side, cause: `sniper-check` or `sniper-attack`) through the reader, writer, projector, `PlayRecords`, `ReplaySteps`, and the page's latest text. The side's state gains a count of reductions (default 0); the printed `San` stays as recorded. Rules decides the actual SAN: by day printed minus reductions; at night min(printed + 2, 7) minus reductions, never below the printed (E1.76). Replace every read of the SAN for a trigger (`ScenarioA1Sniper.Triggers` / `SniperActivationNumber` callers) with the actual one. When it falls below 2, the same commit eliminates that side's Sniper counter (`instance-eliminated`), and no further attacks follow. 4a's dr 1 against an enemy Sniper writes `san-reduced` (cause `sniper-attack`) for the eliminated Sniper's side.
2. **Sniper Check (R71.10).** After an effective Sniper attack (dr 1 or 2), if the target Location holds units of the attacked side that may take it (unpinned, not TI, armed, Good Order Infantry, not having fired or moved this Player Turn), that side gets a pending choice (a new kind `sniper-check`, pass 70's pattern: `ChoicePending`, `ChoiceKindOf`, `DescribeChoice`, `PlanChoose`'s resume, the projector's `PendChoice`, `GameGate`, `ChoiceOptionText`): take it or not. Taking it commits every eligible unit. The DR is made at the answer's commit; Rules decides the DRM (one leader's leadership when directing another unit, none alone; -1 each hero; -1 each crew or HS equivalent, a squad -2; the EX's three cases are tests) and the result (Final DR <= 2 eliminates the Sniper with `san-reduced` cause `sniper-check`; 3 pins it); every participant becomes TI (the existing `asl:ti`); a concealed participant in the LOS of a Good Order enemy ground unit within 16 hexes loses its "?" (A12.141, pass 70's sight table). The choice's audience: decide from what the options name (they name the target side's own units; if they name nothing the other side may not know, it may be public; say which you chose and why). The answer may come in the other side's Player Turn: the hand-over handles it. A Sniper Check DR calls no Sniper.
   - **What "has fired or moved this Player Turn" reads:** read the state for Prep, First, Final, Bounding Fire markers and for movement this Player Turn. If no state fact says a unit moved this Player Turn (frame B found none for Infantry), add the smallest one the projector derives from the events (not a recorded fact), say so first in the report, and name it so the gate's skip list can find it.
   - A Sniper attack resumed after the choice runs the triggers still to resolve, in DR order (the existing resume calls `AddSniperAttacks`): keep that order.
3. **A pinned Sniper** forfeits further attacks that Player Turn (4a cleared its pin at the CCPh's end; check it holds).

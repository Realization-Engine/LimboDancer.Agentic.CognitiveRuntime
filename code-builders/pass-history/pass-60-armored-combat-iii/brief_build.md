## Hard rules
- Rules live in `LimboDancer.Domains.Asl.Rules` alone: every ASL rule is a calculator there that takes facts and returns a verdict. Play reads the state and the map, hands the facts over, and writes the events; it decides no rule. LOS and range stay in Maps. The Rules project references only Abstractions. Tests of Rules reach its public members only.
- The tables of ruling R60.2 are small Rules tables with their page. Do NOT change any transcription JSON, case matrix, package manifest, or the catalog: that would pin the packages again.
- Absent-safety (ruling R60.3): every fact you add to a record (an event payload, a facts record kept as JSON) is nullable or defaulted and `JsonIgnore` when null/default, so a game recorded before the pass reads and replays exactly as it did. A positional record gains a fact as an `init` property. A rule that changes the result of an attack that could be made before the pass is applied only when the record carries the pass's fact for it, and that fact is taken from the record at replay (among the facts `WithRecordedMapFacts` or its fire equivalent keeps), never recomputed from the state. For each new fact, say what the projector's record check does with an old record that lacks it.
- A side's view never shows what that side may not know.
- Do not over-engineer. Match the surrounding code's naming, comment density, and idiom. No em-dashes anywhere (code comments, texts shown to players, docs). A hex in a player-facing text is written in brackets like [G4].
- Shell: never a heredoc, never `sed -i`, never a multi-line `python -c`, never a bare `python -`, never `cd` into a folder of the repository (a hook refuses these; a refusal is a rule broken, do not route around it), never `git add`, never `grep -r` over src/ASL in Bash (use the Grep tool). A script is a file written with the Write tool under `code-builders/pass-history/pass-60-armored-combat-iii/` and run as `python <file> < /dev/null` (PYTHONIOENCODING=utf-8). Files are LF, UTF-8 without BOM.
- Never send an edit and the build or test that depends on it in the same response. Never run two builds or tests at once (they share obj/). Do not edit a project's files while a build of it runs.
- Never touch `src/ASL/boards/`, `.claude/`, `.codex/`, or anything outside `src/ASL`, `docs/ASL`, and `code-builders/pass-history/pass-60-armored-combat-iii`. Never start the Studio (I do). Never stop Visual Studio or any process you did not start.

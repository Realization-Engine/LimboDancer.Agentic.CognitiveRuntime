## 1. Outcome

- **The card library (R22.2).** `ScenarioCardLibrary` holds the built-in cards, embedded and read-only, and the user's cards, one JSON file each under `src/ASL/boards/cards` (untracked live data, as the saved maps are). A user card's name is its id, lower-case letters, digits, and hyphens, never a built-in card's name. Its text and SHA-256 (of the text with LF endings) are read together, again only when the file's write time or length changes; a built-in card's hash is read once. `Save` writes only a card valid against the catalog, replaces an existing user card only when asked to (the editor asks only for the card it is editing), and writes the file whole before moving it into place; `Delete` removes a user card. The Studio's `LivePlay` holds the library, and the planner, the Play page, and the Scenarios page read cards through it. A game from a user card records its id and hash; when the card has changed or gone, no rule reads it (setup, OB, and Victory Conditions alike), and the refusal says which (R18.1, R19.1).
- **The minimal card (R22.3).** A card whose sides have no OB groups: boards and two sides, each side with its SAN, its own ELR, and an edge that may be unnamed (basis `none`; a named edge with no basis is recorded as manufactured under R0.3); the date may give only a month and year, or neither (0). It sets up by hand, with no OB, order, or area checks. Its Victory Conditions name no outcomes (checked), so the players judge the result; its Turn Record Chart still ends the game. SSR tokens are checked against the date as the game will see it, so Extreme Winter without a month and year is refused in the editor, not at setup.
- **The card editor (R22.1).** A Studio page, `/units/cards/edit`, starts from a minimal card, a copy of a built-in card (under a new id), or one of the user's cards, and edits every field: the scalar fields as inputs (including each side's printed Battlefield Integrity total and the playable hexrows' board, which a copy keeps), the OB groups, SSRs, and Victory Conditions as JSON in the card format, with a picker that adds a catalog counter line to a group (the counter it adds is the one it shows). It validates on every change, including the id's form and an id another user card already holds, and a side ELR on a card with an OB; a side's change of nationality carries the Turn Record Chart's and the Scenario Defender's references with it. It saves only a valid card; a user card can be deleted.
- **The form retired (R22.4).** The Play page's new-game form is gone: a new game names a card (built-in, the user's, or a minimal card), its id and label, and the Balance, and shows the start the card gives (boards, sides with their ELR, SAN, and edges, date, SSR tokens, Scenario Defender). The page reads a card again when its text changes. The Scenarios page lists the user's cards and links each card to the editor, and says whether the game evaluates a card's Victory Conditions. The setup action still accepts a start without a card, so recorded games and the planner's tests replay unchanged, and such a game still loads on the Play page; the user's live games are left as they are.
